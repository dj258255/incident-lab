# 근거 조사 기록

카탈로그 각 세션의 근거(사건 실재 여부, 수치·연도·회사, E 등급 적정성)를 웹 원문으로 검증한 기록입니다.
판정 기준은 CATALOG.md 0-3절의 근거 등급 정의를 따릅니다.

기록 형식은 세션당 네 줄입니다. `주장`(카탈로그 행이 말하는 것) → `출처`(URL과 인용문, 원문을 직접 열어 확인했는지 검색 스니펫만 봤는지 표시) → `판정`(등급 유지·변경과 그 이유) → `메모`(글 쓸 때 주의할 점, 인용하면 안 되는 수치).

## 조사 결과 요약

78건 중 대부분은 기존 등급이 타당했고, 등급이 바뀐 것이 5건, 등급은 그대로지만 서술을 고친 것이 여럿입니다. 전부 CATALOG 12절과 해당 행에 반영했습니다.

**등급 변경**

- **A14 XID Wraparound [E2 → E1]**: Sentry가 2015-07-20 자사 장애를 블로그에 공개한 1차 포스트모템 확인.
- **B12 memcache lease [E2 → E1]**: NSDI '13 논문 §3.2.1 원문 확인. Facebook이 자사 프로덕션 문제와 실측을 직접 공개한 1차 문헌입니다.
- **B20 500마일 이메일 [E1 → E2·일화]**: 저자가 FAQ에서 각색을 인정하고 로그도 남아 있지 않다고 밝혔습니다. 기업 포스트모템이 아닙니다.
- **B23 Shopify [E1 → E2]**: 아키텍처 소개 글이지 장애 회고가 아닙니다.
- **B22 Facebook 2021 [E1 → E1·축소]**: 라벨만 정정했습니다.

**세션 폐기**

- **B17 밴쿠버 지수 절삭**: 사건 근거는 멀쩡한데 이미 완성된 F17과 재현 계획이 100% 겹칩니다. F17에 흡수하고, 살리려면 DB 컬럼 타입 쪽으로 주제를 갈아야 합니다.

**출처 없는 수치를 지운 것**

- **B23의 "전체 용량 20% 잠식"**: Shopify 공식 문서 어디에도 없어 삭제했습니다. 이런 수치 하나가 카탈로그 전체의 신뢰를 깎습니다.
- **B21 "인터넷 절반", B22 "7시간", B10 "Go monotonic clock 도입 계기", B05 "AWS 장애"**: 전부 공식 문서 근거가 없어 인용 금지 목록에 넣었습니다.
- **B48 "1,200만 시계열", B47 "54시간", B35 "GPS 9TB"**: 마찬가지로 1차 출처가 없습니다. 앞의 둘은 실측값으로 대체하면 되고, 9TB는 "수 테라바이트"로 낮춰야 합니다.

**이전 검증 기록이 재현되지 않은 것**

- **B51의 국내 실장애 회고 "parallelStream 남용으로 인한 장애 경험기"(2019)**: 앞선 검증 로그에 "확인"으로 적혀 있었지만 이번에 3회 재검색해도 나오지 않았습니다. 그때 URL을 남기지 않은 게 원인으로 보입니다. 승격 근거를 Oracle javadoc 원문으로 갈아끼웠습니다. **앞으로 모든 근거에 URL을 남겨야 합니다** — 이게 이번 조사에서 얻은 가장 실용적인 교훈입니다.

**재현 자체가 안 되는 설계를 잡은 것**

- **B43 expand-contract**: PG 11(2018-10)부터 상수 기본값 컬럼 추가는 재작성 없이 끝납니다. 공식 문서가 "very fast even on large tables"라고 못 박아서, 최신 PG에 그냥 걸면 밀리초에 끝나 재현에 실패합니다.
- **B31 ThreadLocal 누수**: Tomcat이 기본값으로 스스로 정리하고 스레드를 갱신해버립니다. 오히려 "WAS가 대신 막아주고 있었다"를 글의 하이라이트로 삼는 게 낫습니다.
- **B18 DST**: `java.time`은 예외 없이 조용히 시각을 밀어버립니다. 앞서 적은 대로입니다.
- **B33**: 제목의 부등호가 뒤집혀 있었습니다. 장애 조건은 "앱 keep-alive < LB idle timeout"입니다.

**그 밖의 서술 수정**

- **A11 세미싱크**: 근거로 적힌 PlanetScale 글은 자사 장애 회고가 아니라 기술 해설이었습니다.
- **A20 데브시스터즈**: 원문은 24노드 중 16노드 영향이고 원인은 ballast 스크립트가 Block Device를 덮어쓴 사고입니다. 우리 재현이 축소판입니다.
- **A21 Figma**: "무중단"이 아니라 작업당 약 30초 부분 저하(요청 약 2% 드롭)였습니다.
- **B07 Discord, B11 우아한형제들**: 둘 다 1차 출처는 확인됐지만 "장애"가 아니라 만성 운영 문제 회고와 지표 이상 분석입니다. 사건화하면 원문과 어긋납니다.

등급은 그대로 두되 글 쓸 때 조심할 것들은 각 파일의 `메모` 줄에 있습니다. 예를 들어 A05(VACUUM)는 현행 PG 공식 문서에 해당 경고 문장이 없어 공식 문서 인용 대신 실측으로 보여야 하고, R02는 "1분 내 복구" 수치를 원문에서 재확인하지 못해 "수 분 내"로 완화해야 합니다.
