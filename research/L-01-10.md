## L01 무한 루프
- 주장: 피드백 경로가 안 묶이면 한 요청이 도구 호출을 무한 증폭. arXiv에 63건 예산 초과 사고 카탈로그(달러 손실 문서화)와 "Infinite Agentic Loops" 논문 존재
- 출처: arXiv 2606.04056 "Token Budgets: An Empirical Catalog of 63 LLM-Agent Budget-Overrun Incidents" https://arxiv.org/abs/2606.04056 : 21개 오케스트레이션 프레임워크의 63건 확인 사고, 각 건 GitHub 이슈 인용, 달러 손실은 "보고된 경우" 기재(예: 단일 사용자 4일 $235) (원문)
- 출처: arXiv 2607.01641 "When Agents Do Not Stop: Uncovering Infinite Agentic Loops in LLM Agents" https://arxiv.org/abs/2607.01641 : "feedback path is not effectively bounded"일 때 단일 요청이 모델·도구 호출로 증폭 → cost exhaustion·DoS. 6,549개 레포 분석, 68건 IAL 확인 (원문)
- 판정: E2 유지 : 두 논문 모두 실재하고 행의 서술("피드백 경로", "63건", "달러 손실")이 논문 초록과 일치. 개별 사고가 기업 포스트모템은 아니므로 E1 승격은 부적절
- 메모: 63건 카탈로그의 달러 손실은 전 건이 아니라 "보고된 경우만" 문서화 — 글에서 "63건 전부 달러 손실 문서화"로 쓰지 말 것. 카탈로그 행 표현("달러 손실 문서화")은 현행 유지 가능 수준

## L02 인젝션
- 주장: OWASP LLM Top 10의 LLM01(최다 악용). 지식베이스 문서 하나가 오염되면 그걸 검색하는 모든 사용자가 감염
- 출처: OWASP GenAI "LLM01:2025 Prompt Injection" https://genai.owasp.org/llmrisk/llm01-prompt-injection/ : LLM01 정의·간접 인젝션("input from external sources, such as websites or files")·RAG 저장소 문서 변조 공격 시나리오까지 원문에 명시 (원문)
- 출처: Greshake et al. arXiv 2302.12173 "Not what you've signed up for" https://arxiv.org/abs/2302.12173 : "strategically injecting prompts into data likely to be retrieved"로 직접 인터페이스 없이 LLM 앱을 원격 공격, Bing Chat 등 실제 시스템 대상 시연 (원문)
- 판정: E2 유지 : 취약점 분류·간접 인젝션·RAG 시나리오 모두 OWASP 원문 확인. 단 표현 수정 필요(아래 메모)
- 메모: "최다 악용"은 OWASP 원문에 없는 표현 — LLM01은 Top 10의 "1위 항목"일 뿐, 페이지에 most exploited/most common 서술 없음. 행 표현을 "1위 항목"으로 고칠 것. "문서 하나 오염 → 검색하는 모든 사용자 감염"도 OWASP 원문 문장은 아니고 메커니즘 서술이므로 Greshake 논문(검색될 데이터에 주입) 인용으로 뒷받침하는 편이 안전

## L03 KV캐시 선점
- 주장: GPU 캐시 90% 초과 시 시퀀스 선점 시작, 지속 선점은 성능 저하 상태, swap 모드는 긴 컨텍스트 복원에 수백 ms
- 출처: vLLM 공식 문서 "Optimization and Tuning" https://docs.vllm.ai/en/stable/configuration/optimization/ : 선점 조건은 "KV cache space is insufficient"(캐시 공간 부족)이며, 경고문 "preempted by PreemptionMode.RECOMPUTE ... This can affect the end-to-end performance" 원문 확인. "90% 초과 시 선점" 문구는 문서에 없음. V1 기본 선점 모드는 SWAP이 아니라 RECOMPUTE("recomputation has lower overhead in the V1 architecture") (원문)
- 출처: (보조) 같은 문서 GitHub 사본 https://github.com/vllm-project/vllm/blob/main/docs/configuration/optimization.md : 잦은 선점 시 gpu_memory_utilization 증가 등 완화책 동일 확인 (원문)
- 판정: E2 유지(단 행 수치 2건 수정 필요) : 선점·성능 저하 경고는 공식 문서 원문 그대로 실재. 그러나 "90%"와 "swap 수백 ms"는 문서에 없는 서술
- 메모: 재현 설계에 영향 있는 오류 — (1) 90%는 선점 임계값이 아니라 gpu_memory_utilization(KV 캐시 사전 할당 비율) 기본값에서 온 혼동으로 보임. 선점은 "캐시 공간 부족" 시 발생. 행을 "KV 캐시 공간 부족 시 선점"으로 고칠 것. (2) "swap 복원 수백 ms"는 공식 문서에 수치 없음 + V1 기본이 RECOMPUTE라 swap 전제 자체가 구식 — 수치 인용 금지 목록에 추가 권고. (3) num_preemptions_total 메트릭 이름은 이 페이지에선 "Prometheus로 누적 선점 수 관측 가능"이라고만 확인(정확한 메트릭 명칭은 미검증, 검색 도구 오류로 한도 소진)
