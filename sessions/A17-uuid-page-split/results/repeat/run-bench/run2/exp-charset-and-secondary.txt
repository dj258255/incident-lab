  seq_noidx           400,000행     4.8초 데이터    64.6MB 인덱스     0.0MB
  seq_idx             400,000행     5.4초 데이터    64.6MB 인덱스    10.5MB
  uuid4bin_noidx      400,000행     6.8초 데이터   109.8MB 인덱스     0.0MB
  uuid4bin_idx        400,000행     7.8초 데이터   109.8MB 인덱스    18.5MB
  uuid4char8_noidx    400,000행     6.6초 데이터   125.0MB 인덱스     0.0MB
  uuid4char8_idx      400,000행     8.0초 데이터   125.0MB 인덱스    32.6MB

==================================================================
## 1) 세컨더리 인덱스 하나가 PK 종류별로 얼마나 커지는가
==================================================================
  PK                           인덱스 크기     seq 대비       데이터 증가
  BIGINT 8바이트                  10.5MB      1.00배        0.0MB
  BINARY(16)                   18.5MB      1.76배        0.0MB
  CHAR(36) utf8mb4             32.6MB      3.10배        0.0MB
  CHAR(36) ascii               31.6MB      3.01배        0.0MB

  세컨더리 인덱스의 잎에는 인덱스 컬럼과 PK 값이 함께 들어갑니다.
  PK 가 넓으면 인덱스도 그만큼 넓어집니다. 인덱스가 여러 개면 그만큼 곱해집니다.

==================================================================
## 2) CHAR(36) 의 대가 중 폭의 몫과 문자셋의 몫
==================================================================
  BINARY(16)           데이터   109.8MB
  CHAR(36) ascii       데이터   123.0MB  (+13.2MB, 1.12배)
  CHAR(36) utf8mb4     데이터   125.0MB  (+2.0MB, ascii 대비 1.02배)

  BINARY(16) → CHAR(36) ascii 가 폭의 몫이고,
  ascii → utf8mb4 가 문자셋의 몫입니다.

  각 조건 1회 실행입니다. 값은 조건마다 같은 시드로 만든 같은 UUID 열입니다.
