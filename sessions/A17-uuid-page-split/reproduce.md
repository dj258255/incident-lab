# 재현 기록

실행한 명령과 출력을 그대로 붙입니다. 도커 컴포즈가 찍는 컨테이너·볼륨 생성 줄은 분량만
차지해서 `grep -v`로 걷어낸 곳이 있고, 그 경우 명령줄에 그대로 남겼습니다.

## 1. 환경 기동

호스트 사양입니다. 조건 간 비교가 목적이라 절대 시간은 이 장비 안에서만 뜻이 있습니다.
다른 세션의 절대 시간과 비교하면 안 됩니다.

```console
$ uname -srm
Linux 5.14.0-570.33.2.el9_6.aarch64 aarch64

$ nproc
2

$ free -g | head -2
               total        used        free      shared  buff/cache   available
Mem:              11           3           2           0           6           8
```

MySQL 컨테이너는 `compose.yml`에서 `cpus: 2`, `mem_limit: 2g`, 버퍼 풀 256MB입니다.
호스트가 2코어이므로 적재 스크립트와 MySQL이 같은 코어를 나눠 씁니다.

```console
$ cd sessions/A17-uuid-page-split
$ docker compose build load
 Image a17-load  Built

$ docker compose up -d --wait mysql
 Container a17-mysql  Waiting
 Container a17-mysql  Healthy
```

## 2. 파일럿과 설계 수정

본 실험 전에 50만 행으로 먼저 돌려 규모를 정했습니다. 이 단계에서 UUIDv7 생성기의 문제를
찾았습니다.

첫 파일럿의 UUIDv7은 타임스탬프를 2,000행마다 한 번씩 올렸습니다. 결과가 이랬습니다.

```console
$ docker compose run --rm load python bench.py --arm uuid7_bin --rows 500000 \
    --chunk 100000 --out /results/pilot-uuid7_bin.json
  총 27.5초, 18,200행/초, 테이블 137.9MB, 행당 289.2바이트, 적재 중 디스크 읽기 379페이지
```

같은 조건의 UUIDv4가 136.8MB에 행당 286.8바이트였으니, 시간 정렬 PK가 랜덤과 같은 크기를
낸 셈입니다. 실제 적재 속도가 초당 약 2만 행이므로 밀리초당 20행이 맞는데 2,000행을 한
밀리초에 몰아넣고 있었습니다. 100배 흩어진 조건이었습니다.

`--uuid7-rows-per-ms` 를 20으로 고쳐 다시 쟀습니다.

```console
$ docker compose run --rm load python bench.py --arm uuid7_bin --rows 500000 \
    --chunk 100000 --out /results/pilot-uuid7_bin.json
  총 23.3초, 21,474행/초, 테이블 141.8MB, 행당 297.3바이트, 적재 중 디스크 읽기 10페이지
```

흩어짐을 100분의 1로 줄였는데 결과가 나아지지 않았습니다. 행당 바이트는 289.2에서 297.3으로
오히려 조금 늘었고, 같은 정의로 계산한 공간 효율은 56.0%에서 54.5%로 내려갔습니다.
설계 실수를 고쳐도 결과가 개선되지 않으므로 이것이 UUIDv7의 실제 성질이라고 보고,
밀리초 안 카운터를 넣은 조건을 추가했습니다.

이 두 점은 나중에 본문의 서술을 한 번 더 고치게 만들었습니다. "밀리초 안에 많이 몰릴수록
나빠진다"는 용량 반응 관계를 이 데이터로 주장할 수 없습니다. 2,000행과 20행 사이에
사실상 차이가 없으므로, 순서가 깨지는 순간 곧바로 50%대로 내려앉고 그 뒤로는 정도가
거의 무관하다고 읽는 것이 맞습니다.

```console
$ docker compose run --rm load python bench.py --arm uuid7_counter --rows 500000 \
    --chunk 100000 --out /results/pilot-uuid7_counter.json
  총 28.1초, 17,809행/초, 테이블 84.7MB, 행당 177.5바이트, 적재 중 디스크 읽기 4페이지
```

141.8MB가 84.7MB가 됐습니다. 여기서 본 실험 조건을 다섯 개로 확정했습니다.
파일럿 결과는 `results/pilot-*.json` 에 남아 있습니다.
