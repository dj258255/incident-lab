# 실험 16. 승격 재시도 간격을 직접 잰다
#
# 실험 7까지는 "승격이 실패하면 1,250개마다 다시 시도한다"를 문서 인용과 관찰 정합으로만
# 적었다. 확장 이벤트 lock_escalation 은 성공한 승격만 남기기 때문이다.
# sys.dm_db_index_operational_stats 의 index_lock_promotion_attempt_count 는
# 실패한 시도까지 센다. 이 카운터로 간격을 직접 잰다.
#
# 방법: 옆 세션이 마지막 행 하나를 잡아 테이블 X 락을 막는다(실험 7의 조건 B).
#       승격은 계속 실패하므로 시도만 쌓인다. 갱신 행 수를 바꿔가며 시도 증가분을 센다.
#       케이스마다 옆 세션을 새로 세워 앞 회차가 새지 않게 한다.

  갱신행    잡은락    시도 증가   승격 증가
  3000      3010      1          0
  4000      4012      2          0
  4300      4313      2          0
  5600      5617      3          0
  6000      6018      3          0
  8200      8224      5          0
  20000     20056     15         0
  40000     40110     31         0

==================================================================
## 정리
==================================================================

  시도 횟수 = floor(잡은락 / 1250) - 1 이 8회 전부에서 맞습니다.

    3,010 → 2-1 = 1      20,056 → 16-1 = 15
    5,617 → 4-1 = 3      40,110 → 32-1 = 31

  **재시도 간격 1,250 을 관찰 정합이 아니라 직접 쟀습니다.**

  그리고 첫 시도가 2,500 락에서 일어납니다. 5,000 이 아닙니다.
  문서의 5,000 은 검사를 시작하는 값이 아니라 **승격이 성공하는 조건**입니다.
  엔진은 그보다 훨씬 일찍부터, 락 1,250개마다 계속 두드려 보고 있습니다.
  실험 9에서 "1,250마다 검사하고 5,000 넘긴 참조를 승격시킨다"고 적은 규칙의
  앞부분이 이 실험으로 확인됩니다.

  운영 함의: 승격이 "안 났다"는 것은 조건이 아직 안 맞는다는 뜻이지
  엔진이 포기했다는 뜻이 아닙니다. 40,000행 배치는 그 한 문장 동안
  31번 승격을 시도했고, 옆 세션이 커밋하는 순간 다음 시도가 성공합니다.
