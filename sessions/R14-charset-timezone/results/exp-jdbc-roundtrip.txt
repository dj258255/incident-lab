# JDBC 를 거친 왕복
# MySQL 8.4.3
# 커넥터: mysql-connector-j-9.1.0.jar

  LocalDateTime 을 넣고 같은 커넥션으로 읽습니다. DATETIME 과 TIMESTAMP 를 나란히
  두는 이유는, 앞 절에서 본 대로 DATETIME 은 벽시계를 그대로 담고 TIMESTAMP 는
  UTC 로 바꿔 담기 때문입니다. 변환이 어디서 일어나는지가 이 표의 질문입니다.

    JVM 기본 시간대 = Etc/UTC
    서버 time_zone = SYSTEM / 세션 = SYSTEM
  
    조건                           값        DATETIME 로 왕복              TIMESTAMP 로 왕복            
    default                      plain    2026-06-15T12:00           2026-06-15T12:00          
                                 gap      2026-03-08T02:30           2026-03-08T02:30          
                                 dup      2026-11-01T01:30           2026-11-01T01:30          
    connectionTimeZone=LOCAL     plain    2026-06-15T12:00           2026-06-15T12:00          
                                 gap      2026-03-08T02:30           2026-03-08T02:30          
                                 dup      2026-11-01T01:30           2026-11-01T01:30          
    connectionTimeZone=SERVER    plain    2026-06-15T12:00           2026-06-15T12:00          
                                 gap      2026-03-08T02:30           2026-03-08T02:30          
                                 dup      2026-11-01T01:30           2026-11-01T01:30          
    NY-forced                    gap      TIMESTAMP 거부: Data truncation: Incorrect datetime value: '2026-03-08 02:30:00' for column 'as_timestamp' at row 11
    NY-forced                    plain    2026-06-15T12:00           2026-06-15T12:00          
                                 gap      2026-03-08T02:30           null                      
                                 dup      2026-11-01T01:30           2026-11-01T01:30          
  
    넣은 값은 셋 다 그대로입니다.
      plain 2026-06-15T12:00, gap 2026-03-08T02:30, dup 2026-11-01T01:30
    돌아온 값이 이와 다르면 그 구간에서 드라이버나 서버가 변환한 것입니다.

  서버에 실제로 무엇이 들어갔는지도 확인합니다(드라이버를 안 거친 값).
  +---------------------------------+-------------------------+-------------------------+
  | label                           | as_datetime             | as_timestamp            |
  +---------------------------------+-------------------------+-------------------------+
  | default:plain                   | 2026-06-15 12:00:00.000 | 2026-06-15 12:00:00.000 |
  | default:gap                     | 2026-03-08 02:30:00.000 | 2026-03-08 02:30:00.000 |
  | default:dup                     | 2026-11-01 01:30:00.000 | 2026-11-01 01:30:00.000 |
  | connectionTimeZone=LOCAL:plain  | 2026-06-15 12:00:00.000 | 2026-06-15 12:00:00.000 |
  | connectionTimeZone=LOCAL:gap    | 2026-03-08 02:30:00.000 | 2026-03-08 02:30:00.000 |
  | connectionTimeZone=LOCAL:dup    | 2026-11-01 01:30:00.000 | 2026-11-01 01:30:00.000 |
  | connectionTimeZone=SERVER:plain | 2026-06-15 12:00:00.000 | 2026-06-15 12:00:00.000 |
  | connectionTimeZone=SERVER:gap   | 2026-03-08 02:30:00.000 | 2026-03-08 02:30:00.000 |
  | connectionTimeZone=SERVER:dup   | 2026-11-01 01:30:00.000 | 2026-11-01 01:30:00.000 |
  | NY-forced:plain                 | 2026-06-15 12:00:00.000 | 2026-06-15 16:00:00.000 |
  | NY-forced:gap                   | 2026-03-08 02:30:00.000 | NULL                    |
  | NY-forced:dup                   | 2026-11-01 01:30:00.000 | 2026-11-01 05:30:00.000 |
  +---------------------------------+-------------------------+-------------------------+

  각 조건 1회 실행입니다.
