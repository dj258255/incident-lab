# 물리 복제 슬롯도 같은 방식으로 위험한가
# PostgreSQL 17.5 (Debian 17.5-1.pgdg130+1)
# 조건마다 40초 쓰기, 각 1회 실행입니다.

  비교는 시작 WAL 이 아니라 관측 창 안의 증가분으로 합니다.
  앞 조건이 남긴 값이 시작값을 오염시켜도 증가분은 살아남습니다.

### 대조군: 슬롯 없음
  max_slot_wal_keep_size = -1
  슬롯 = 없음
  WAL 240.0MB → 256.0MB (증가 16.0MB)

### 논리 슬롯, 컨슈머 없음
  max_slot_wal_keep_size = -1
  슬롯 = log_slot(logical)
  WAL 256.0MB → 816.0MB (증가 560.0MB)
  슬롯 상태 = log_slot extended 붙잡은 800 MB

### 물리 슬롯, 스탠바이 없음
  max_slot_wal_keep_size = -1
  슬롯 = phys_slot(physical)
  WAL 256.0MB → 832.0MB (증가 576.0MB)
  슬롯 상태 = phys_slot extended 붙잡은 806 MB

### 물리 슬롯 + 상한 64MB
  max_slot_wal_keep_size = 64MB
  슬롯 = phys_slot(physical)
  WAL 256.0MB → 256.0MB (증가 0.0MB)
  슬롯 상태 = phys_slot lost 붙잡은 ?

==================================================================
## 정리
==================================================================
  조건                                 상한     WAL 증가       슬롯 없음 대비
  대조군: 슬롯 없음                         -1      16.0MB          1.00배
  논리 슬롯                         logical     816.0MB         51.00배
  물리 슬롯                        physical     832.0MB         52.00배
  물리 슬롯 + 상한 64MB                  64MB       0.0MB          0.00배

  슬롯 없음보다 크게 늘면 그 슬롯이 WAL 을 붙잡고 있는 것입니다.
  논리와 물리가 비슷하게 늘면 붙잡는 메커니즘이 같다는 뜻이고,
  상한을 걸었을 때만 안 늘면 max_slot_wal_keep_size 가 물리에도 걸린다는 뜻입니다.

  설정을 되돌립니다.
  각 조건 1회 실행입니다.
