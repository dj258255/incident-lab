# Debezium 하트비트: 켜고 action.query 까지 줘도 publication 밖이면 소용없다
# PostgreSQL PostgreSQL 17.5 (Debian 17.5-1.pgdg130+1
# Debezium Server 3.0, 조건마다 90초 관측, 1회 실행
# 스냅샷은 snapshot.mode=no_data 로 걷어 냈고, 싱크는 스레드 방식으로 바꿨습니다.

### A. 하트비트 없음
  하트비트 0ms, action.query no, 대상 쓰기 no
  publication = watch_log
  90초 동안
    슬롯 지연     11.1MB → 334.3MB  (증가 323.1MB)
    pg_wal        256MB → 336MB
    하트비트 행   0 → 0 (90초에 0회)
    other_log     299600행 / watch_log 0행

### B. 주기만(action.query 없음)
  하트비트 3000ms, action.query no, 대상 쓰기 no
  publication = watch_log
  90초 동안
    슬롯 지연     11.1MB → 335.3MB  (증가 324.2MB)
    pg_wal        256MB → 336MB
    하트비트 행   0 → 0 (90초에 0회)
    other_log     299600행 / watch_log 0행

### C. 주기+query / 테이블이 publication 밖
  하트비트 3000ms, action.query yes, 대상 쓰기 no
  publication = watch_log
  90초 동안
    슬롯 지연     11.1MB → 333.8MB  (증가 322.6MB)
    pg_wal        352MB → 336MB
    하트비트 행   1 → 30 (90초에 29회)
    other_log     299600행 / watch_log 0행

### E. 주기+query / 테이블이 publication 안
  하트비트 3000ms, action.query yes, 대상 쓰기 no
  publication = dbz_heartbeat, watch_log
  90초 동안
    슬롯 지연     11.2MB → 66.4MB  (증가 55.3MB)
    pg_wal        352MB → 256MB
    하트비트 행   1 → 30 (90초에 29회)
    other_log     301200행 / watch_log 0행

### D. 하트비트 없이 대상 테이블에도 쓰기
  하트비트 0ms, action.query no, 대상 쓰기 yes
  publication = watch_log
  90초 동안
    슬롯 지연     22.3MB → 27.5MB  (증가 5.2MB)
    pg_wal        256MB → 256MB
    하트비트 행   0 → 0 (90초에 0회)
    other_log     299600행 / watch_log 299600행
