# 스탠바이 절벽 재시도
# PostgreSQL 17.5 (Debian 17.5-1.pgdg130+1) · 프라이머리 + 스트리밍 스탠바이 · t 200000 행
# 쓰기 클라이언트 6, 트랜잭션당 서브트랜잭션 200, 각 조건 30초
# 5절 실패의 원인이던 행 락 겹침을 없앴습니다. 클라이언트마다 자기 키 범위를 씁니다.
# 조건마다 두 컨테이너를 재시작하고 같은 방식으로 데워 캐시 상태를 맞춥니다.

  A 기준선(둘 다 없음) 스탠바이   1276회  프라이머리 UPDATE    66000  ASSIGNMENT     0  스탠바이 subtrans(읽기/히트) 0/0  지연 3초
  B 롱TX만                 스탠바이   1114회  프라이머리 UPDATE    66000  ASSIGNMENT     0  스탠바이 subtrans(읽기/히트) 0/0  지연 3초
  C 서브TX만              스탠바이   1286회  프라이머리 UPDATE    62400  ASSIGNMENT   936  스탠바이 subtrans(읽기/히트) 0/72788  지연 3초
  D 롱TX + 서브TX (GitLab) 스탠바이   1006회  프라이머리 UPDATE    63600  ASSIGNMENT  1890  스탠바이 subtrans(읽기/히트) 0/115420156  지연 3초

  프라이머리 쓰기량 62400에서 66000, 폭 5%
  폭이 25% 안입니다. 스탠바이 처리량을 조건 사이에 비교할 수 있습니다.

  ASSIGNMENT 가 0 이면 스탠바이는 오버플로를 통보받지 못합니다.
  그 경우 subtrans 읽기가 0 인 것은 재현 실패가 아니라 조건 미성립입니다.
