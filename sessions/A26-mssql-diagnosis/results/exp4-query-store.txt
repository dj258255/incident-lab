# 실험 4. 캐시가 비면 범인도 사라진다

  실험 3은 계획 캐시로 범인을 찾았습니다. 그 방법에는 전제가 있습니다.
  **계획이 캐시에 남아 있어야 합니다.** 사고가 지나간 뒤에 들여다보면
  이미 밀려났을 수 있는데, 그 상황을 안 만들어 봤습니다.

==================================================================
## 4-1. Query Store 를 켠다
==================================================================

  Query Store 상태       READ_WRITE / capture ALL

  캡처 모드를 ALL 로 둡니다. 기본값 AUTO 는 가벼운 쿼리를 안 담는데,
  **조사에서 찾고 싶은 것이 늘 무거운 쿼리인 것은 아닙니다.**
  리터럴로 흩어진 쿼리는 하나하나가 가벼워서 AUTO 에서 빠질 수 있습니다.

==================================================================
## 4-2. 부하를 걸고 두 곳에서 본다
==================================================================

  시점                         DMV 계획     DMV 논리읽기 QS 쿼리      QS 논리읽기
  부하 직후                  3              187800           6              187805

==================================================================
## 4-3. 캐시가 비면
==================================================================

  사고가 지나가고 시간이 흐르면 계획이 밀려납니다. 메모리 압박, 통계 갱신,
  인덱스 변경, 재시작이 전부 그 원인입니다. 여기서는 그 결과만 만듭니다.

  계획 캐시를 비운 뒤    0              0                7              187819

  **DMV 쪽은 통째로 사라졌습니다.** 3개 계획, 논리 읽기 187800 이
  0 이 됐습니다. `dm_exec_query_stats` 는 이름 그대로 **캐시에 있는 계획의**
  통계이고, 계획이 없어지면 통계도 함께 없어집니다.

  **Query Store 는 그대로 있습니다.** 7개 쿼리, 논리 읽기 187819.
  디스크에 쓰기 때문입니다. 사고가 지나간 뒤에 들여다봐도 남아 있습니다.

==================================================================
## 4-4. Query Store 가 대신 못 하는 것
==================================================================

  그러면 DMV 를 버리고 Query Store 만 보면 되는가. **아닙니다.**

  물어보는 것                   DMV              Query Store
  지금 무엇이 돌고 있나     dm_exec_requests 못 한다
  지금 누가 누구를 막고 있나 dm_tran_locks    못 한다
  지난 사고의 범인 쿼리     캐시에 남아야 **남아 있다**
  그때의 실행 계획            밀려나면 없음 **버전별로 보관**
  계획이 바뀌어 느려진 것  못 본다       **계획 회귀로 본다**

  **Query Store 는 지난 일을 보는 도구이고 DMV 는 지금을 보는 도구입니다.**
  실험 2의 블로킹 사슬은 Query Store 로 못 찾습니다. 지금 누가 누구를 막고
  있는지는 저장되는 값이 아니기 때문입니다.

  그래서 순서가 이렇게 갈립니다.
    사고가 **지금** 나고 있다        DMV. 대기 -> 사슬 -> 뿌리
    사고가 **지나갔다**              Query Store. 그 구간의 쿼리와 계획
    같은 쿼리가 **갑자기 느려졌다**  Query Store 의 계획 회귀

==================================================================
## 정리
==================================================================

  실험 3의 방법에는 전제가 있었습니다. **계획이 캐시에 남아 있어야 합니다.**
  캐시를 비우자 3개 계획과 논리 읽기 187800 이 통째로 사라졌습니다.
  사고 대응이 늦어지면 범인이 이미 없을 수 있습니다.

  **Query Store 는 그 자리를 메웁니다.** 디스크에 쓰므로 재시작에도 남고,
  구간별로 쪼개 두므로 "어제 그 시간대"를 물을 수 있습니다.

  다만 **대체재가 아니라 짝**입니다. 지금 누가 막고 있는지는 Query Store 가
  모릅니다. 진단 순서에서 DMV 는 앞자리, Query Store 는 뒷자리입니다.

  켤 때 주의할 것이 하나 있습니다. **캡처 모드 기본값 AUTO 는 가벼운 쿼리를
  안 담습니다.** 실험 3에서 본 리터럴로 흩어진 범인은 하나하나가 가벼워서
  그 그물에서 빠질 수 있습니다. 그런 조사를 할 생각이면 ALL 로 둡니다.
