# 백업 검증을 주기적으로 돌리고 실패하면 알린다
# 5회차 · 3초 간격 · 3회차에 일부러 백업을 손상시킵니다
# 알림 경로 자체를 검증합니다. 보냈다고 믿는 것과 도착한 것은 다릅니다.

  회차     판정 실패검사     알림  내용
       1 **환경**       -1       sent  환경 실패: 검사 컨테이너가 안 떴습니다
       2 **환경**       -1       sent  환경 실패: 검사 컨테이너가 안 떴습니다
       3 **환경**       -1       sent  환경 실패: 검사 컨테이너가 안 떴습니다
       4 **환경**       -1       sent  환경 실패: 검사 컨테이너가 안 떴습니다
       5 **환경**       -1       sent  환경 실패: 검사 컨테이너가 안 떴습니다

  알림 로그(alerts.log):
    [회차 1] [환경] 환경 실패: 검사 컨테이너가 안 떴습니다
    [회차 2] [환경] 환경 실패: 검사 컨테이너가 안 떴습니다
    [회차 3] [환경] 환경 실패: 검사 컨테이너가 안 떴습니다
    [회차 4] [환경] 환경 실패: 검사 컨테이너가 안 떴습니다
    [회차 5] [환경] 환경 실패: 검사 컨테이너가 안 떴습니다

  검사 실패 0건, 환경 실패 5건, 알림 5건
  **전부 환경 실패입니다. 백업 검사는 한 번도 안 돌았습니다.**
  알림이 나간 것과 백업이 검증된 것은 다릅니다. 이 회차는 백업에 대해
  아무것도 말해 주지 않습니다.

  이 스크립트의 종료 코드는 4 입니다. cron 이나 systemd timer 에 걸면
  0 이 아닌 종료가 그대로 실패 신호가 됩니다. 실무 배치 예시:
    */30 * * * * /opt/lab/tools/verify-scheduler.sh || /opt/lab/tools/page-oncall.sh
