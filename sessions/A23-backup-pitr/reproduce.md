# A23 재현 기록

## 환경

| 항목 | 값 |
|---|---|
| 원본 | MySQL 8.4.3 (a23-mysql), log-bin, gtid-mode=ON, sync_binlog=1 |
| 복구 대상 | MySQL 8.4.3 (a23-restore) |
| 도구 | percona/percona-server:8.4 (a23-tools) — `mysqlbinlog` 확보용 |
| 일시 | 2026-07-29 |

## 실행

```console
$ docker compose up -d
$ ./scripts/exp1-pitr.sh     # PITR 본 실험, 약 10초
$ ./scripts/exp2-traps.sh    # 함정 4종, 약 15초
```

## 실험 2: 함정 4종 (results/exp2.txt)

### GTID 겹침

```console
$ docker exec -i a23-mysql mysql -uroot -plab < full.sql
ERROR 3546 (HY000) at line 24: @@GLOBAL.GTID_PURGED cannot be changed:
the added gtid set must not overlap with @@GLOBAL.GTID_EXECUTED

$ mysqldump ... --set-gtid-purged=OFF 로 다시 뜨면
  GTID_PURGED 구문 없음 → 같은 서버에도 복원 가능
```

### 도구 부재

```console
$ docker exec a23-mysql ls /usr/bin | grep '^mysql'
mysql
mysqladmin
mysqldump
mysqlsh

$ docker exec a23-mysql mysqlbinlog --version
bash: line 1: mysqlbinlog: command not found

대안: mysqlbinlog  Ver 8.4.10-10 for Linux on aarch64 (Percona Server (GPL))
```

### 조용한 스킵

```console
재적용 전 행 수 1500
$ mysql < recover.sql        # 방금 적용한 것과 똑같은 파일을 한 번 더
종료 코드 0 (0이면 성공)          <- stderr 없음
재적용 후 행 수 1500  → 늘어난 행 0 건
GTID 차집합(새로 실행된 트랜잭션) ''
```

### binlog 만료

```console
$ SELECT @@binlog_expire_logs_seconds;
2592000                                   -- 30일

$ SET GLOBAL binlog_expire_logs_seconds = 1;  FLUSH BINARY LOGS;
  binlog 파일 수 4개 → 2개
  가장 오래된 파일 binlog.000001 → binlog.000004
```
