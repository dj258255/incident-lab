# 실험 12. 0 이 나왔을 때 계기를 의심하는 법

  실험 8에서 두 값이 0 으로 나왔고 그 0 을 못 믿었습니다. 0 에는 "안 썼다"와
  "못 잡았다"가 섞여 있습니다. 가르는 방법은 하나입니다.
  **그 계기로 0 이 아닌 값을 한 번 만들어 보는 것.**

==================================================================
## 12-1. 버전 저장소 계기가 살아 있는가
==================================================================

  RCSI 를 켜면 갱신할 때마다 이전 버전이 tempdb 로 갑니다. 같은 계기로
  그것이 보이면 계기는 정상이고, 실험 8의 0 은 진짜 0 입니다.

  조건                                   RCSI       tempdb 버전    이 DB 가 만든 버전
  A RCSI 끄고 30만 행 갱신           OFF        0MB              0MB
  B RCSI 켜고 30만 행 갱신           ON         83MB             83MB

  **계기가 살아 있습니다.** 같은 쿼리로 83MB 를 잡아냈습니다.
  그러므로 실험 8에서 온라인 인덱스 빌드 중에 나온 0 은 **못 잡은 것이 아니라
  실제로 버전 저장소를 안 쓴 것**입니다.

  온라인 빌드는 동시 변경을 tempdb 버전 저장소가 아니라 **자기 안에서** 다룹니다.
  빌드 중에 들어온 변경을 따로 모아 두었다가 마지막에 합치는 구조라, 스냅샷
  격리가 쓰는 버전 저장소와는 다른 자리입니다.

==================================================================
## 12-2. 로그를 세 번째 계기로 받친다
==================================================================

  실험 8의 온라인 두 줄은 파일 I/O 카운터 하나로만 서 있었습니다.
  트랜잭션 단위 카운터가 온라인에서만 안 잡혔기 때문입니다.
  경로가 또 다른 계기를 세웁니다. sys.dm_db_log_stats 는 **마지막 로그 백업 이후
  쌓인 로그**를 알려 줍니다. FULL 에서 백업을 뜨고 재면 그 구간의 순수한 양입니다.

  조건                                   파일 카운터 dm_db_log_stats
  오프라인 인덱스 빌드            68.1MB           68.1MB
  온라인 인덱스 빌드               101.4MB          101.3MB

  **온라인 빌드에서도 두 계기가 같은 방향을 가리킵니다.** 실험 8에서 비어 있던
  자리를 다른 DMV 로 채웠습니다. 파일 카운터는 물리 쓰기라 조금 더 크게 나오고
  log_stats 는 로그 레코드의 양이라 조금 작습니다. 그 차이는 로그 블록이 채워지며
  같은 블록을 여러 번 밀어내는 몫입니다.

==================================================================
## 정리
==================================================================

  실험 8이 남긴 두 구멍은 **결과가 아니라 계측의 문제**였습니다.

  0 을 보고할 때는 그 계기로 0 이 아닌 값을 만들어 본 적이 있어야 합니다.
  RCSI 를 켜서 버전 저장소를 부풀리자 같은 쿼리가 그것을 잡았고, 그러므로
  온라인 빌드 중의 0 은 **실제로 안 쓴 것**이라고 말할 수 있게 됐습니다.
  양성 대조가 없으면 그 0 은 아무 말도 못 합니다.

  두 번째 계기가 안 잡히면 세 번째를 찾습니다. 트랜잭션 단위 카운터가 온라인
  빌드를 못 잡은 것은 그 빌드가 짧은 내부 트랜잭션을 쓰기 때문이고, 그렇다면
  **트랜잭션 단위가 아닌 계기**를 세우면 됩니다. dm_db_log_stats 는 백업 지점
  기준이라 트랜잭션 경계와 무관합니다.

  운영으로 옮기면 이렇게 됩니다.
    0 을 근거로 무언가를 주장하기 전에 그 계기의 양성 대조를 먼저 만든다
    계기 하나가 안 잡히면 **경로가 다른 계기**를 찾는다. 같은 계열은 같이 눈이 먼다
    수치가 두 계기에서 다르면 어느 쪽이 무엇을 세는지부터 확인한다
