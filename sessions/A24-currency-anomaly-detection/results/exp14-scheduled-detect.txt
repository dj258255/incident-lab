# 실험 14. 주기적으로 도는 탐지 배치

  2026-08-05 10:00:00 부터 60분 창을 6번 밀며 돕니다.
  사고는 그중 한 창에 들어 있고, 배치는 그것을 모릅니다.

  사고는 2026-08-05 12:55:00.000 에 있습니다. 계정 40개가 같은 참조로 두 번씩 받았습니다.
  세 번째 창이 끝나기 5분 전이라, 지연 워터마크 10분이면 다시 읽는 범위에 듭니다.

### A 워터마크만, 늦은 도착 없음
  회차   창 시작               읽은 행 새 경보 누적 경보

  2        2026-08-05 11:00:00.000  506        0          0

  6        2026-08-05 15:00:00.000  497        0          40
  최종 경보 40건 (기대 40건)

### B 워터마크만, 늦은 도착 있음
  회차   창 시작               읽은 행 새 경보 누적 경보
  1        2026-08-05 10:00:00.000  505        0          0

  6        2026-08-05 15:00:00.000  497        0          0
  최종 경보 0건 (기대 40건)

### C 워터마크를 10분 물려 둠, 늦은 도착 있음
  회차   창 시작               읽은 행 새 경보 누적 경보
  1        2026-08-05 10:00:00.000  505        0          0

## 정리
==================================================================

  A 늦은 도착이 없으면             40/40
  B 늦은 도착이 있으면             0/40
  C 워터마크를 물려 두면          40/40

  **A 는 사고가 든 회차에서 정확히 잡습니다.** 창을 밀며 도는 것만으로 됩니다.
  회차마다 새 경보만 세므로 같은 사고를 두 번 알리지 않습니다. 유일 제약이
  (탐지기, 계정, 참조)로 걸려 있어 배치를 다시 돌려도 중복이 안 쌓입니다.

  **B 가 놓칩니다.** 배치가 그 창을 지나간 뒤에 같은 시각의 행이 도착했고,
  워터마크는 이미 그 앞에 있어 다시 안 봅니다. **오류도 경보도 없이 사라집니다.**
  created_at 은 그 일이 일어난 시각이지 DB 에 도착한 시각이 아닙니다.
  둘의 순서가 다를 수 있다는 것이 이 구멍의 뿌리입니다.

  **C 는 워터마크를 창 끝이 아니라 10분 뒤로 물려 둡니다.** 매번 겹치는 구간을
  다시 읽으므로 늦게 온 행을 잡습니다. 다시 읽어도 유일 제약이 중복 경보를
  막아 주기 때문에 겹쳐 읽는 것이 안전합니다.

  다만 **지연 폭이 도착 지연보다 넓어야 합니다.** 처음에 사고를 창 한가운데
  두었을 때는 10분 지연으로 못 물러나 C 도 놓쳤습니다. 얼마나 늦게 도착하는지
  모르면 그 폭을 정할 수 없고, 그것은 **DB 가 아니라 지급 경로가 답할 문제**입니다.

  운영으로 옮기면 이렇게 됩니다.

    워터마크를 표에 두고 **경보 기록과 같은 트랜잭션에서** 옮긴다
    워터마크를 창 끝이 아니라 **도착 지연보다 넓게 물려** 둔다. 겹쳐 읽는다
    같은 사고의 정의를 유일 제약으로 못 박는다. 겹쳐 읽어도 중복이 안 쌓인다
    경보는 조사 대상이지 회수 근거가 아니다. 근거는 이 세션의 대사 쿼리가 만든다

  마지막 줄이 중요합니다. 주기 배치가 하는 일은 **사람을 부르는 것**까지입니다.
  실험 2와 9가 보인 대로 회수 근거는 결정론적 대사에서 나와야 하고, 그것은
  경보를 받은 뒤에 사람이 창을 정해 돌리는 쿼리입니다.
