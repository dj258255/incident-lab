==============================================================
실험 2. 쓰기가 들어오는 중에 INT를 BIGINT로 바꾼다 (3000000행)
==============================================================

방법 A. ALTER TABLE ... MODIFY id BIGINT (한 방)
  적재 행, MB
  먼저 온라인으로 시도한다
    ERROR 1146 (42S02) at line 1: Table 'spoon.sponsor_a' doesn't exist
  엔진이 거부한다. 타입 변경은 테이블을 다시 만들어야 하므로 COPY만 가능하다.
  COPY로 실행한다
    ERROR 1146 (42S02) at line 1: Table 'spoon.sponsor_a' doesn't exist
  소요 .163228000초

방법 B. expand-contract 3단계
  적재 3000000행

  1단계 expand: BIGINT 신규 컬럼 추가
    소요 5.444122000초
  2단계 backfill: 기존 행을 청크로 채운다
    청크 151회, 소요 107.226131000초
    남은 NULL 5건 (백필 중 들어온 새 행)
  3단계 잔여 백필: 백필 중에 들어온 새 행을 마저 채운다
    소요 1.042900000초
    (실제 전환은 여기서 애플리케이션이 두 컬럼을 함께 쓰도록 배포한 뒤
     컬럼명을 교체한다. 이 실험은 DB 쪽 작업만 잰다)
  전체 소요 114.148320000초
  전환 중 쓰기 7,346건 · 성공 7,346 · 실패 0
  성공한 쓰기의 p95 4.0ms · 최대 52ms

판단 기준은 소요 시간이 아니라 전환 중 쓰기 실패 건수다.
