전제: 주 10013행, 보조는 그보다 뒤처져 있다 (실험 1)

## 2-1. 꼬리 로그를 WITH NORECOVERY 로 — 주가 역할을 내려놓는다
BACKUP LOG successfully processed 4 pages in 0.002 seconds (13.671 MB/sec).
  주의 상태: RESTORING
  주에 쓰기 시도 → Sqlcmd: Error: Microsoft ODBC Driver 18 for SQL Server : Can...

## 2-2. 보조: 꼬리까지 복원하고 연다

  보조의 상태: ONLINE — 이제 이쪽이 주다

## 2-3. 검산 — 유실 0 인가
  승격된 보조: 10013행 (장애 직전 주: 10013행)
  백업 안 됐던 마지막 3행: 3 / 3  ← 꼬리 로그가 나른 몫
  승격된 쪽에 쓰기: 성공 (10014행)

결론: MySQL 반동기는 강등을 모른 채 승격해 334건을 잃었지만(A23·3장),
로그 전달은 주가 살아 있는 한 꼬리 로그가 유실 0 을 만든다. 꼬리를 못 뜨는
상황 — 주 디스크가 통째로 죽은 때 — 의 유실 폭이 곧 로그 백업 주기다.
