## 1) 락 판별 세 방법을 같은 순간에
   같은 부하에서 세 방법을 번갈아 재고, 값과 비용을 나란히 놓습니다.

   방법                                중앙값       최대        조회 비용 중앙
   data_lock_waits                    28       28           0.69ms
   sys.innodb_lock_waits              21       28           1.83ms
   ENGINE STATUS(LOCK WAIT)            7        7           0.79ms

   ENGINE STATUS 텍스트 크기 중앙 10,344바이트, 잘림 0/40회

## 1-b) 대기가 없을 때 세 방법의 비용
   워커를 띄우지 않고 같은 방법을 같은 횟수로 재 봅니다.

   방법                              대기 중앙        조회 비용 중앙         부하 있을 때 대비
   data_lock_waits                     0           2.75ms              4.01배
   sys.innodb_lock_waits               0           2.34ms              1.28배
   ENGINE STATUS(LOCK WAIT)            0           1.32ms              1.67배

   ENGINE STATUS 텍스트 크기 중앙 4,509바이트, 잘림 0/40회

   읽는 법. 세 값이 같은 방향으로 움직이면 어느 것을 써도 판별은 됩니다.
   갈리는 것은 비용과 형태입니다. data_lock_waits 는 숫자를 바로 주고,
   sys 뷰는 같은 정보에 질의 텍스트를 붙이는 대신 조인이 붙고,
   ENGINE STATUS 는 매번 수만 바이트를 파싱해야 하며 트랜잭션이 많으면 잘립니다.
   1초 간격 샘플러에 넣을 것은 가장 싼 것이어야 합니다.
