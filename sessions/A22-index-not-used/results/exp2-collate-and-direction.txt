# COLLATE 우회와 형변환 방향
# MySQL 8.4.3 · orders 300000행 / legacy 30000행 / nums 300000행
# 인덱스를 탔는지는 핸들러 카운터로 봅니다. 풀스캔 값이 크면 못 탄 것입니다.

## 1. 문자셋 불일치 조인을 COLLATE 로 넘길 수 있는가

  (a) 아무것도 안 함           결과 30000건 인덱스탐색 30015  인덱스순회 60004     풀스캔 0        160ms
  (b) COLLATE 를 명시             **거부됨**
        ERROR 1253 (42000) at line 3: COLLATION 'utf8mb4_0900_ai_ci' is not valid for CHARACTER SET 'latin1'
  (c) CONVERT 로 맞춤             결과 30000건 인덱스탐색 30015  인덱스순회 60004     풀스캔 0        159ms

  legacy 를 utf8mb4 로 올린 뒤
  (d) 스키마를 통일            결과 30000건 인덱스탐색 30015  인덱스순회 60004     풀스캔 0        149ms

   위 네 줄은 옵티마이저가 legacy(3만행)를 선두에 놓아 orders 의 인덱스만 씁니다.
   어느 쪽 인덱스가 죽는지 보려면 orders 를 선두로 고정해 legacy 를 찾게 해야 합니다.
   아래는 STRAIGHT_JOIN 으로 방향을 고정한 같은 질문입니다.

  (e) 방향 고정, 아무것도 안 함 결과 30000건 인덱스탐색 33     인덱스순회 330015    풀스캔 0        195ms
  (f) 방향 고정, CONVERT         결과 30000건 인덱스탐색 33     인덱스순회 330015    풀스캔 0        208ms
  (g) 방향 고정, 스키마 통일 결과 30000건 인덱스탐색 300032 인덱스순회 300015    풀스캔 0        923ms

## 2. 형변환의 방향이 대칭인가
   orders.order_no 는 VARCHAR, nums.code 는 INT 입니다. 둘 다 값 150000 이 있습니다.

  (a) 문자열컬럼 = 숫자리터럴 결과 0건   인덱스탐색 15     인덱스순회 300004    풀스캔 0        121ms
  (b) 숫자컬럼 = 문자열리터럴 결과 1건   인덱스탐색 15     인덱스순회 5         풀스캔 0        55ms
  (c) 문자열컬럼 = 문자열(대조) 결과 1건   인덱스탐색 15     인덱스순회 5         풀스캔 0        64ms
  (d) 숫자컬럼 = 숫자(대조)  결과 1건   인덱스탐색 15     인덱스순회 5         풀스캔 0        59ms
