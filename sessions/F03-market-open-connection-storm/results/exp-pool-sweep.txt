# 풀 크기 스윕과 max-threads 반복
# 조건마다 3회 반복입니다.

==================================================================
## 1) 풀을 키우면 어떻게 되는가
==================================================================
  부하 차단 허용 수는 풀 크기와 같게 둡니다(기본 설계와 같은 관계).

  주의. 앞선 집계에서 차단 건수가 전부 0 으로 찍혔습니다. k6 요약의 카운터 이름이
  cnt_503 인데 shed 로 찾고 있었고, shed 가 들어간 줄은 dur_503_shed 뿐이라 콜론 뒤가
  avg= 로 시작해 숫자가 안 나옵니다. 값이 빈 문자열이 되어 0 으로 표시됐습니다.
  절반을 버린 조건이 하나도 안 버린 조건과 같아 보였습니다. 아래는 다시 뽑은 값입니다.

      풀     총 요청    성공(200)    차단(503)     집계 p95     성공만 p95    회차
     10    9,999      5,194      4,805     53.63ms      54.55ms     3
     20    9,999      9,384        615     54.03ms      54.12ms     3
     50    9,999      9,999          0     54.14ms      54.14ms     3
    100    9,999      9,999          0     54.10ms      54.10ms     3

  읽는 법. 풀을 키워 초당 처리가 늘고 p95 가 안 오르면 문서의 권고가 이 조건에서는
  안 맞는 것입니다. 처리는 느는데 p95 가 같이 오르면 대기가 애플리케이션에서
  DB 로 옮겨간 것이고, 그것이 문서가 경고하는 상태입니다.
  차단(503) 건수가 줄어드는 것은 받아 준 것이지 빨라진 것이 아닙니다.
