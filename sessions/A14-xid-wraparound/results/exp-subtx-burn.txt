# 쓰기를 하는 SAVEPOINT 가 XID 를 얼마나 더 쓰는가
# PostgreSQL 17.5 (Debian 17.5-1.pgdg130+1), 데이터베이스 postgres
# 트랜잭션 2000건, 세이브포인트 0 1 4 16

  XID 위치는 pg_snapshot_xmax 로 읽습니다. pg_current_xact_id 는 부르는 것만으로
  XID 를 할당하므로 그것으로 재면 측정이 결과를 바꿉니다.

  세이브포인트   XID 소비   넣은 행     행당 XID     소요
            0개         6000         6000          1.000     1.0초
            1개         4000         4000          1.000     0.8초
            4개        10000        10000          1.000     1.2초
           16개        34000        34000          1.000     3.5초

==================================================================
## 정리
==================================================================
        세이브포인트        트랜잭션당 XID           세이브포인트 없음 대비
            0개            3.00                  1.00배
            1개            2.00                  0.67배
            4개            5.00                  1.67배
           16개           17.00                  5.67배

  트랜잭션 하나가 세이브포인트 n 개에서 쓰기를 하면 XID 를 n+1 개 씁니다.
  본문 하나에 서브트랜잭션 n 개이기 때문입니다.

  초당 트랜잭션 1,000건을 가정하면 wraparound(2,000,000,000)까지
    세이브포인트  0개       7.7일
    세이브포인트  1개      11.6일
    세이브포인트  4개       4.6일
    세이브포인트 16개       1.4일

  autovacuum 이 정상이면 이 날짜에 도달하지 않습니다. 이 표가 말하는 것은
  autovacuum 이 멈춰 있을 때 남은 시간이 세이브포인트 수만큼 짧아진다는 것입니다.
  A19 가 다루는 SLRU 압박과 이 세션이 다루는 XID 소진이 같은 원인에서 나옵니다.

  각 조건 1회 실행입니다.
