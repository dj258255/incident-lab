# 재현의 한계, 전수 점검

이 저장소의 세션은 끝에 **"못 한 것"** 절을 둡니다. 한계를 적는 것이 규약(CONVENTIONS 2장)이기
때문입니다. 그런데 한계를 적어 두기만 하면 그것대로 굳습니다. 그래서 **적어 둔 한계를 전부 다시
꺼내 "왜 못 했나"를 하나씩 판정**했습니다. 이 문서는 그 판정의 결과입니다.

질문은 이것이었습니다. **"재현 불가능한 것을 빼면 거의 다 재현하고 싶은데, 안 한 이유가 뭔가.
의미가 없어서인가, 몰라서인가, 아니면 그냥 안 한 것인가."**

## 판정 기준

한계 항목 하나하나를 다섯으로 나눴습니다. 판정 장비는 12코어 맥 · 32GB · Docker VM 7.7GB 입니다.

| 등급 | 뜻 | 처리 |
|---|---|---|
| **A** | 원리적으로 불가 | 그대로 둔다. 없는 원문을 만들 수는 없다 |
| **B** | 이 환경에서 불가 | 조건을 명시하고 둔다. 클라우드 실계정·커널 계측·상용 에디션 |
| **C** | **가능한데 안 함** | 우선순위를 매겨 실행한다 |
| **D** | 범위 밖 | 남긴다. "이건 왜 안 다뤘나"에 답할 자리가 필요하다 |
| **E** | 이미 해결됨 | 문구를 고친다 |

## 집계: 145건

| 등급 | 건수 | 비중 |
|---|---|---|
| A 원리적 불가 | 7 | 5% |
| B 환경 불가 | 35 | 24% |
| **C 가능한데 안 함** | **64** | **44%** |
| D 범위 밖 | 33 | 23% |
| E 이미 해결 | 6 | 4% |

**C가 44%였습니다.** "못 했다"고 적은 것의 절반 가까이가 사실은 **장비도 도구도 있는데 안 한 것**
이었습니다. 이 숫자가 이 점검의 결론이고, 그래서 C부터 실행했습니다.

## 점검이 실제로 바꾼 것

C를 실행하자 **기존 결론이 뒤집힌 자리**가 나왔습니다. 이것이 한계를 다시 꺼내 보는 이유입니다.

| 세션 | 실행한 것 | 결과 |
|---|---|---|
| **B52** | PostgreSQL 커서 대조 | **처방이 두 엔진에서 정반대**(117배). MySQL 결론을 그대로 쓰면 틀린다 |
| **A22** | 결과 집합 크기별 배수 곡선 | LIMIT 1 에서 1,034.5배, 50만 행에서 1.2배. **"1,969배"를 인용할 때 결과 집합 크기를 반드시 함께 적어야 한다** |
| **A22** | `COLLATE` 임시 처방 | **에러 1253.** 문자셋이 다르면 문법 자체가 성립하지 않는다. 스키마를 맞추는 것만이 답 |
| **R17** | 파티션 수가 조회에 물리는 비용 | 프루닝 질의는 파티션 수와 무관. **파티션의 이득은 삭제 하나**뿐이고 단건 조회는 11.2배 손해 |
| **A17** | 페이지 충전율 직접 측정 | `INNODB_BUFFER_PAGE` 로 재니 uuid4 가 50~60% 구간에 4,588 페이지를 쌓아 둔 것이 분할의 흔적 |
| **A01** | `pt-online-schema-change` | 2.6배 오래 걸리는 대신 p95 4,576ms → 16ms |
| **A14** | `vacuum_failsafe_age` 대조 | VACUUM 2.45초 → 0.67초, 그 뒤 조회 247배 |
| **A02** | 커넥션 풀 캐스케이드 | **무관한 엔드포인트가 43% 실패** — 한 테이블의 DDL이 서비스 전체로 번지는 경로 |
| **A06** | 해소 4안 대조 | 최종금액 2000을 만든 것은 **재시도뿐**이었다 |
| **32편** | "못 한 것" 절이 없던 10편 | 구조 통일. 한계를 안 적은 것이지 한계가 없는 것이 아니었다 |

## 점검 과정에서 스스로 밟은 결함

실행하면서 **이미 발행한 수치를 무효로 만드는 결함**을 여럿 찾았습니다. 숨기지 않고 적습니다.

- **R17 파티션 실험의 날짜 폭이 파티션 수를 따라갔습니다.** 하루치 행 수가 365배 차이 나
  프루닝 이득처럼 보인 `286ms → 0.87ms` 가 사실은 **결과 집합이 줄어든 것**이었습니다.
  날짜 폭을 365일로 고정해 고쳤습니다.
- **A22 의 EXPLAIN 컬럼 인덱스를 잘못 읽어** `type` 과 `key` 가 전부 `None` 이었습니다.
  `partitions` 를 `type` 으로, `possible_keys` 를 `key` 로 읽고 있었습니다.
- **R17 재실행 첫 회가 빈 테이블에서 돌았습니다.** DELETE 가 0.11초로 끝나 무효였는데,
  **소요 시간이 이상하다는 것만이 그것을 알려 줬습니다.**
- **BSD `seq` 가 `seq 1 0` 에 두 줄을 냅니다.** "0개 조건"이 조용히 2개가 됐습니다
  (규약 11장 도구 절에 박아 뒀습니다).
- **Docker VM 이 7.7GB 뿐입니다.** `mem_limit: 4g` 세션을 동시에 여러 개 못 띄웁니다.
